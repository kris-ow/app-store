# app-store — personal Android app workflow

A monorepo of small Android apps built conversationally with Claude Code,
published to a self-hosted F-Droid repo, installed on the owner's phone via
an F-Droid client (Droid-ify / Neo Store / official F-Droid).

The owner (sole user) drives this by chatting in Claude Code: "build me an
app that does X." This file tells you, future Claude session, how the repo
is laid out and how to do that.

## Stack & conventions
- Kotlin + Jetpack Compose, Material 3, AGP 8.7, Compose BOM (see `gradle/libs.versions.toml`)
- One app = one Gradle module under `apps/<name>/`
- Package prefix: `dev.kowczarek.<app_id>` — `<app_id>` is lowercase, no dashes
- minSdk 26, target/compile SDK 35, JVM 17
- Versions live in the catalog (`gradle/libs.versions.toml`) — don't hardcode

## Adding a new app
1. Copy `_templates/android-app/` to `apps/<app_id>/`
2. Replace every `__APP_ID__` with the app id (lowercase identifier)
3. Replace every `__APP_NAME__` with the user-facing name
4. Rename `src/main/kotlin/dev/kowczarek/__APP_ID__/` to use the real id
5. Fill in `apps/<app_id>/SPEC.md` with the agreed scope (do this WITH the user)
6. Gradle settings.gradle.kts auto-discovers — no manual `include()` needed

## Build / test loop
Local dev (USB-connected phone or emulator):
```
./gradlew :apps:<app_id>:installDebug   # build debug + install
adb logcat -s <app_id>                  # tail logs
```
Release build (rarely needed locally; CI does this):
```
./gradlew :apps:<app_id>:assembleRelease
```

The `release` signing config reads `KEYSTORE_PATH` / `KEYSTORE_PASSWORD` /
`KEY_ALIAS` / `KEY_PASSWORD` from env vars. If they're unset, the release
build will fail — that's intentional, so you don't accidentally ship
unsigned APKs locally.

## Signing keys — read before touching
- ONE keystore (`release.jks`) signs both APKs and the F-Droid repo index
- It is **never** committed. CI reads it from the `KEYSTORE_BASE64` secret
- One-time setup (owner does this, not Claude):
  ```
  keytool -genkey -v -keystore release.jks -keyalg RSA -keysize 4096 \
    -validity 10000 -alias appstore
  base64 -w 0 release.jks   # paste output into GitHub secret KEYSTORE_BASE64
  ```
  Required GitHub Actions secrets:
  - `KEYSTORE_BASE64` — base64-encoded keystore
  - `KEYSTORE_PASSWORD`
  - `KEY_ALIAS` (default: `appstore`)
  - `KEY_PASSWORD`
- **If this keystore is lost, every existing install on the phone must be
  uninstalled before new versions can be installed.** Back it up offline.

## F-Droid repo
- `fdroid/config.yml` — repo metadata; `repo_url` must match the public URL
- `fdroid/repo/` — generated by `fdroid update`; deployed to GitHub Pages
- Public URL: `https://kris-ow.github.io/app-store/fdroid/repo`

## CI flow
- `pr-check.yml`: lint + assembleDebug on PRs (no signing)
- `build-and-publish.yml`: on push to `main`, builds signed release APKs,
  copies them to `fdroid/repo/`, runs `fdroid update`, deploys to Pages

## What NOT to do
- Don't commit `*.jks`, `*.keystore`, `local.properties`, or `keystore.properties`
- Don't change `applicationId` or the keystore alias after an app's first
  release — F-Droid treats it as a new app and the phone won't upgrade
- Don't bump `versionCode` non-monotonically; F-Droid uses it for "is this
  an upgrade?" decisions
- Don't rename the GitHub repo or change `repo_url` after the phone has
  added the F-Droid repo — the signature is tied to that URL
